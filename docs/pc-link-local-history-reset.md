# NETLAB-03B-5C — 双方の確認履歴を一括初期化（端末署名キーは維持）

**開発プレビューのみ。実機での両端末確認は未実施。これは恒久ペアリングの失効同期ではない。**

AndroidとWindowsそれぞれで、過去にQR-v3で署名検証した相手の公開鍵指紋を保存できる。これらは認証履歴のメモであり、権限・接続資格・自動再接続許可として使用しない。今回の追加機能は、履歴を全消去したい場合や暗号化ファイルの破損を復旧したい場合に、**端末自体のP-256署名キーを失効させずに、ローカル記録だけ消去**するためのもの。

## Windows（PC側）

- 事前に起動中のペアリングセッションを終了してから、`ChappyCompanion.exe --verified-clear` をユーザーが明示実行する。
- 画面に内容を表示し、大文字の `CLEAR` と入力した場合だけ `verified-phones-v1.dpapi` をローカル削除。拒否・別の入力・標準入力の終了では変更しない。
- 履歴が破損して一覧表示できなくても、ファイルの内容を復号せずに消去できる。
- `--verified-clear` は `--start` や `--pair` などネットワーク起動オプションと併用不可。LAN待受や新しい認証トークンの作成は行わない。
- 現在のWindowsユーザーのP-256署名キー（DPAPIで保護されている `device-identity-v1.dpapi`）には触れない。PCの鍵自体を失効させるには従来の別コマンド `--identity-revoke` が必要。

## Android（スマホ側）

- Network Lab → 端末キー管理 → 確認済みPCの記録 → **「すべての確認履歴を消去」**。
- 別の確認ダイアログで**「すべての記録を削除」**を押したときだけ、ローカルの暗号化履歴ファイルと専用AES-GCM保存鍵を削除。Android KeyStoreの端末用P-256署名キーは残る。
- 一覧表示に失敗した場合にも消去ボタンを表示し、破損した履歴の復旧を可能にする。正常な空の履歴ではボタンは表示しない。
- ネイティブAndroid処理は前面の信頼済みFlutterホストのMethodChannelに限定し、`.chappy` JavaScriptには公開しない。消去はWi-Fi接続がなくても可能。
- リセット後はそのスマホの確認履歴が空になるが、Windows側に保存された履歴や鍵は変更されない。

## 安全上の区別

- **ローカル確認履歴の削除は、リモート端末の鍵の失効・ペアリング解除・ネットワーク切断ではない。** WindowsとAndroid両方の履歴を消す場合は、それぞれの機器で操作する。
- QR-v1/v2/v3の一時認証、本人確認、旧版の接続検証の安全条件は変更しない。確認履歴の存在・不存在が今後の認証成否を決定することはない。
- 端末の署名キーそのものを漏洩・紛失した場合は履歴消去だけでは不十分。別の鍵失効・新規作成と相手機器の再確認が必要。
- Android/Windowsの同時に動作する実機2台による接続と保存の再現、電源断・画面ロック・端末再起動・Windowsアカウント切替は未検証で、正式署名APKの公開は行わない。

## 自動テスト

- Flutter widget/unit: 一覧表示のみでは保存や削除が起きないこと、一括削除ダイアログのキャンセルと承認、破損時の復旧UI、元の端末キー操作へ影響しないホストAPIを確認。
- Windows (実Windows DPAPI): `CLEAR` を入力するまで削除されないこと、破損した暗号化ファイルを安全に消去できること、P-256署名キーの指紋が維持されること、ネットワークを起動しないことを確認。
- Android build: 元のネイティブKeystoreとAtomicFileの消去関数を使い、Flutter解析・テスト・ネイティブKotlinを含むDebug APK生成を同じPRのCIで確認する。
