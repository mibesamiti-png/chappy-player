# NETLAB-03B-7A — 端末鍵の失効・再作成時の安全確認と手動復旧

**開発プレビュー段階。端末キー・確認履歴の削除はローカル操作であり、恒久ペアリングの失効や相手端末への失効通知ではない。Android↔Windowsの実機2台による移行試験は未実施。**

関連：[相互署名QR-v3](pc-link-mutual-qr-v3.md)・[Androidの履歴](pc-link-verified-history.md)・[Windowsの履歴](pc-link-windows-verified-history.md)・[双方の手動公開鍵照合](pc-link-known-key-comparison.md)・[Issue #56](https://github.com/mibesamiti-png/chappy-player/issues/56)。

## 削除前に知っておくこと

- 「確認済みPC・スマホの記録を消す」と「**自分の端末署名用P-256秘密鍵を消す**」は別操作。前者はローカルの指紋メモだけの削除。後者は旧鍵を復元できなくするため、次のQR-v3では公開鍵のSHA-256指紋が変わる。
- この段階で保存している相手の公開指紋は**接続権限ではない**。確認履歴の消去や鍵の削除によって、リモートに実装済みの恒久ペアリングが取り消されるわけではない（恒久ペアリング自体未実装）。
- 一方の端末で鍵や履歴を消しても、**もう一方の端末の公開鍵確認履歴・秘密鍵は自動変更されない**。紛失や盗難を理由に操作する場合、相手の端末でも必要に応じて旧指紋を手動で削除し、必ず新しい使い捨てQR-v3で両方の署名を検証し直す。
- 秘密鍵は公開リポジトリ、ログ、クラウドバックアップ、Notionへ絶対に書き出さない。公開指紋の確認に必要なのは短い文字列で、**秘密鍵をエクスポートする機能は追加しない**。

## Android側：誤削除防止

1. Network Lab → **PC連携用の端末キーを準備・削除**で作成済みの公開鍵指紋を確認する。既存の鍵を使えるなら削除・再生成しない。
2. 「この端末の秘密鍵を削除」を押すと、不可逆な削除・**ローカルに保存した確認済みPCの暗号化履歴の消去**・相手PCには通知されないことが示される。
3. 表示される**公開鍵指紋の末尾8文字（小文字hex）を正確に入力**しない限り、削除ボタンは無効。キャンセル・誤入力ではAndroidのネイティブ削除APIを呼び出さない。
4. ユーザー承認後、Flutterからは表示した**64桁の完全な公開鍵指紋**をTrusted Host MethodChannelへ送る。ネイティブ側も現在のAndroid KeyStore鍵を読み直し、**完全一致しなければ削除を拒否**する。空引数、余計なフィールド、形式違いの要求も拒否する。
5. 鍵が一致して削除できた場合だけ、既存のホスト処理により確認済みPC履歴の暗号化ファイルと専用AES鍵を消す。Androidアプリ本体・音楽・ミニアプリ・他の保存データは変更しない。
6. KeyStore削除後に確認履歴消去などでエラーになった場合、画面側で現在の鍵状態を**再読込して表示を訂正する**。操作の成功／部分失敗が不明なときは「状態を更新」で確認し、必要なら確認履歴ページの明示的な一括初期化を行う。
7. 新しい端末鍵が必要になった場合だけ改めて「端末キーを作成」を実行。新しい公開指紋は**旧鍵と別の識別子**として扱い、新しいQR-v3と両端末の利用者承認・相互署名で再確認する。

## Windows側：同じくローカルでのみ失効

1. `ChappyCompanion.exe --identity-status` で、現在のPC公開鍵指紋を確認する。
2. `ChappyCompanion.exe --identity-revoke` では従来どおり大文字の `REVOKE` が必要。実行前に、PC端末署名キー**およびDPAPIで暗号化されたスマホ確認履歴が削除される**ことをコンソールに明示する。Android側の鍵や指紋履歴には変更を送らない。
3. 必要な場合だけ `ChappyCompanion.exe --identity-create` を明示実行する。旧公開指紋は二度と同一の鍵として復元されない。別のWindowsアカウントで生成した鍵は別の端末IDとして扱う。
4. スマホに残る旧PC指紋はAndroidの「確認済みPCの記録を確認・削除」画面から**別途**手動削除。新しい端末鍵でQR-v3の双方の署名を確認したあと、PCで `SAVE`、Androidで「確認履歴だけ保存」を**それぞれ独立に承認**すれば、新しい公開鍵の記録を保存できる。

## 安全境界と未実施の確認

- 新しいコードはAndroidの**削除リクエストの事前条件と画面確認のみ**を変更する。Windowsの `REVOKE` 文字列や削除処理本体は変更せず、表示警告を補強した。
- Android KeyStoreの実際の秘密鍵削除、Windows DPAPI、暗号化履歴の既存所有者検証、QR-v3の署名プロトコル、Wi-Fi前面制約、.chappy JSへの非公開、APK署名や配布設定は維持。
- Flutter widget：キャンセル・間違った末尾8文字・正しい文字列だけの操作、削除引数の64文字検証、履歴消去が部分失敗した場合の画面の再読込。ネイティブソース契約：現在の鍵指紋との照合・余分な引数の拒否。
- Windows CI：従来のDPAPI削除・再作成・確認履歴削除・コンソールの承認テスト、Windows EXEプレビュー生成。Android CI：Flutter解析/テスト、KotlinビルドとDebug APK生成。
- **実物のAndroid KeyStore上での鍵削除/アプリ再起動/機種変更、Windows↔Androidのキー再登録、OSユーザー切替と失効・通信切断の動作は未検証**。CI成功を実機での安全性の証明とは呼ばない。
