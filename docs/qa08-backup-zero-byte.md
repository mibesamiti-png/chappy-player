# QA-08：Androidバックアップが0KBになる問題

実機報告（2026-11-04）
- Xiaomi 11T Pro / Android 14 / HyperOS 1.0.20
- QA-03: メモ帳起動成功
- QA-04: メモ帳の保存成功（ユーザー報告）
- QA-08: 保存先に0KBの `.chappybackup` が作られる
- QA-09: 0KBのため復元できない
- **バックアップの書き出しは失敗。メモ帳内部のデータは残っている。**
- 端末容量には余裕が少ないため容量不足や外部プロバイダーの動作も確認対象。

## 修正

旧版は `FilePicker.platform.saveFile(bytes: bytes)` から戻り値が
あれば保存成功を表示していた。しかし保存先の実際の容量を検証して
おらず、AndroidのDocumentsProviderが0KBを残しても成功と誤認し得た。

新版では:
1. プレイヤー内部でバックアップを生成し、JSON解析・アプリ件数・
   サイズを確認。アプリの保存データが0件なら出力しない。
2. プライベート一時ファイルへ書き込み、サイズとSHA-256を検査。
3. Androidネイティブの `ACTION_CREATE_DOCUMENT` で保存先を選択。
4. `ContentResolver.openOutputStream(uri, "wt")` へコピー。
5. 書き込みクローズ後に `openInputStream(uri)` で保存先を**読み戻し**、
   バイト数・SHA-256が元データと一致した場合だけ「バックアップ完了」。
6. 失敗はエラー表示。Androidが0KBの保存先を作った可能性があれば
   ユーザーに削除を促し、決して成功扱いしない。
7. 復元で0KBファイルが選択されたら理由を説明し、元のアプリデータは
   一切書き換えない。

### 実機テストが必要

- [ ] メモ帳に「てすと」と保存して、閉じて再び開いても残る
- [ ] バックアップを端末のDownloadsなどへ書き出す
- [ ] ファイルの容量が0KBでない
- [ ] アプリに保存完了のバイト数が表示される
- [ ] 復元画面でそのファイルを選べる
- [ ] 一時的にメモ帳を変更したあと、バックアップを復元すると元の内容に戻る
- [ ] 別の保存先（Xiaomiファイル管理・Google Driveなど）でも確認
- [ ] 保存画面でキャンセル時に成功通知が出ない

**バックアップ成功を確認するまで、Chappy Playerをアンインストール
しないこと。** アンインストールするとアプリ内部データが消える。

バックアップにはミニアプリ本体の`.chappy`は含まれない。
JSON形式で暗号化されていないので、共有先に個人情報が含まれないよう注意。
