# Chappy Player — カメラ動画録画と暗転／バックグラウンド継続の設計

作成日: 2026-11-06。**仕様・実装計画のみ（動画録画は現行正式版 v0.2.4 に未実装）**。

## ユーザー要望

- Chappy Media Lab / Chappy Playerで端末のカメラ映像を動画として録画・保存したい。
- 録画中に画面を真っ黒にして消費電力と眩しさを抑えたい。
- できれば画面を物理的にOFFにしたり、別アプリを使用しても録画を継続したい。
- 既存のカメラ静止画プレビュー・ネイティブマイク・保存データ・正式APK署名を維持する。

## 重要な違い

| モード | 画面・OS動作 | 実装方針 |
|---|---|---|
| 暗転録画（第1段階） | アプリは前面表示のまま。真っ黒な全画面と最低輝度に近い画面を表示するが、**画面パネルは実際にはON** | CameraX録画、Flutter/Androidの画面輝度変更と暗転UIを組み合わせる |
| バックグラウンド録画（第2段階） | ユーザーが開始後、ホーム/アプリ切替/画面ロックでも録画を継続することを目指す | Androidの camera Foreground Serviceが録画を所有し、継続中は明瞭な常駐通知を表示 |
| Androidプライバシー表示 | どちらもOSのカメラインジケーター等は通常どおり動作 | OSのカメラ使用通知・権限表示を隠さない、ユーザーに明示して録画する |

ブラックスクリーンは「ディスプレイOFF」と同義ではない。第1段階だけでは画面ロック後の録画を保証しない。

## 固定機能ID・進捗

| ID | 機能 | 状態 | 必須検証 |
|---|---|---|---|
| CAMREC-01 | CameraX VideoCapture（動画録画・停止） | 未実装 | Android端末で再生できる動画ファイル |
| CAMREC-02 | 録画ファイルの安全なMediaStore保存・共有 | 未実装 | 録画完了後の再生、ギャラリー表示、ファイル名衝突 |
| CAMREC-03 | 音声ON/OFF、カメラ前後、画質選択 | 未実装 | CAMERA/RECORD_AUDIO権限を個別要求、端末非対応の選択肢にフォールバック |
| CAMREC-04 | 暗転UI（黒画面・輝度低下・簡単な復帰） | 未実装 | 画面操作・通話・異常終了・アプリ切替時の輝度復元 |
| CAMREC-05 | 端末の発熱・保存容量・経過時間の録画中表示 | 未実装 | 容量不足、長時間録画、画面回転 |

| CAMREC-09 | ミニアプリからの安全な許可付き制御 | 未実装 | ホスト独自承認＋明示操作＋宣言済権限のみ |

状態は「未実装」「一部実装」「実装済」「要修正」。検証はコード確認・CI・実機を分けて管理する。

## 推奨アーキテクチャ

1. WebViewの `getUserMedia()` は既存の**プレビュー診断**として残す。
2. 長時間の動画保存本体はAndroidネイティブへ分離し、CameraXの `VideoCapture<Recorder>` を第一候補とする。映像ファイルはMediaStoreへ保存し、`VideoRecordEvent.Finalize` で成功/失敗とURIを受け取る。
3. 動画/音声データをJavaScriptブリッジへBase64で流さず、ブリッジにはコマンドと最小の状態（録画中・経過秒・サイズ・保存結果）だけを返す。
4. 同一カメラをWebViewとAndroidが同時に開かないよう、開始前にWebViewのプレビュートラックを停止し、Android録画中は別カメラ操作を拒否する。
5. ミニアプリによる録画は `manifest.json` で `camera` を宣言し、端末権限に加えプレイヤー側で毎回明示的に許可する。音声ONは `microphone` 宣言とAndroid録音権限を追加で確認する。
6. 生映像/生音声/保存先の絶対パスは診断ログへ書かない。外部URLへの送信はしない。
7. ミニアプリからの録画開始にはユーザーが操作する明確なボタンと明示的な状態表示が必要。無操作・非表示の自動録画、隠し録画、バックグラウンドからの任意起動は行わない。

## 第1段階: 暗転録画

- 録画開始 → ユーザー承認 → カメラ権限（音声付きなら録音権限） → CameraX Recorder開始。
- 録画状態が `START` になったら「画面を暗くする」で全画面に黒いUIを表示。端末の画面輝度はアプリウィンドウの `screenBrightness` で最小付近へ（一部端末で真のゼロ輝度が保証されるわけではない）。
- 黒画面では、誤操作防止と回復性のためダブルタップ/長押し等の復帰操作、録画停止操作、録画中の小さな表示を用意する。Androidのカメラインジケーターや権限通知を回避しない。
- 暗転モード退出・停止・Activity終了・例外時には輝度設定を元に戻す。輝度の永続変更はしない。
- 保存中は一時状態を維持。正常停止時にファイルを確定し、保存結果を見せる。容量不足/故障時には失敗を明示し、不完全ファイルを成功扱いしない。
- 録画の最低限の設定: 背面/前面、720p/1080p（端末能力に応じる）、音声ON/OFF、動画を保存する明示ボタン。
- 現段階では暗転時も画面ON。画面OFFやアプリバックグラウンド移行時は安全側に停止/ファイル確定する。

## 第2段階: 画面ロック・他アプリ中でも継続

- AndroidManifestに `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_CAMERA` と `android:foregroundServiceType="camera"` を適切に宣言する。音声付き録画を継続するなら `FOREGROUND_SERVICE_MICROPHONE` と `microphone` type、および `RECORD_AUDIO` を追加する。
- **アプリの画面が可視で、ユーザーが明示操作した時にサービスを開始する。** Android 14以降は使用中権限の条件があり、バックグラウンドから新規camera/microphoneサービスを作ると `SecurityException` 等になる。
- サービスがCameraX recorderを所有し、Flutter ActivityやWebViewのライフサイクルとは独立させる。画面OFF/バックグラウンドでも継続可能かを端末実測で確認。
- 録画中は継続通知（録画中、経過時間、停止ボタン）を表示。通知の停止動作はアプリのUIが閉じても有効にする。無断の再開、再起動時の自動録画はしない。
- OSがカメラ取得を制限・停止した場合は録画を確定し、理由と状態をUIに記録。バッテリー最適化や端末差で継続を保証しすぎない。
- 既存のネイティブマイク波形取得とは別の録音セッションとして整理し、二重マイク使用によるエラーを避ける。
- ワークフローでカメラ用サービスを正式APKに入れる前に、Android Manifestの権限・typeとAndroid 14/15差分をCIで静的検証する。

## UIイメージ

- Chappy Media Lab: `動画を録画` / `録画停止` / `暗転モード` / `保存した動画を見る・共有`。
- 状態: `停止` / `録画開始中` / `録画中 (00:01:23)` / `保存中` / `保存済` / `エラー`。
- 将来のバックグラウンド録画: `画面を消しても継続` を**明示的にON**にした録画だけがサービスを使う。専用の目立つ常駐通知と停止操作を提供する。

## デバイステスト

1. Xiaomi 11T Pro / Android 14で背面・前面カメラから録画し、標準ギャラリーでMP4再生と音声有無を確認。
2. 720p/1080p希望値・実際の解像度を確認。音声なしはマイク権限不要。
3. 20秒の録画と10分以上の録画でファイルのサイズ、終了・再生、発熱を確認。
4. 暗転状態で復帰/停止ができること、暗転解除時とアプリ再起動時に明るさが元に戻ること。
5. 第1段階は画面ロックで録画が止まること（継続を誤認させない）。
6. 第2段階では録画中にホームへ戻る/他アプリを開く/電源ボタンで画面OFFの3ケースを実機確認。失敗時は通知と動画の確定状況を確認。
7. 許可拒否・権限取り消し・通話中・他アプリがカメラ使用中・容量不足・急停止・端末の省電力設定を試す。
8. 既存 .chappy・メモ帳・ASMR設定を上書き更新後も保持。端末の既存アプリをアンインストールしない。
