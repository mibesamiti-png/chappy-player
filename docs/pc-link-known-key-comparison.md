# NETLAB-03B-6A — Androidで過去の確認済みPC指紋と新しいQR-v3を手動照合

**開発プレビュー。Android↔Windowsの実機通信は未検証。恒久ペアリング・遠隔失効・アクセス権限は未実装。**

## この機能が必要な理由

QR-v3の「確認履歴」は、ユーザーが以前にP-256署名で確認し、別途保存を承認したPCの公開鍵SPKI SHA-256指紋のみ。履歴は端末を自動的に認証・許可する資格情報ではない。

PCの公開鍵が予期せず変わると、異なるPC、別Windowsアカウント、PC端末キー再生成、端末の交換や攻撃など、複数の可能性がある。**端末名だけでは同じPCか判定できない**。このため、ユーザーが「このPCの以前の指紋を確認したい」と明示的に選んだ場合に限り、次のQR-v3と照合する。

## Androidの操作

1. Network LabからPC接続確認の画面を開き、「以前確認したPCの公開鍵指紋を選んで照合」を押す。ここではネットワークに接続しない。Android KeyStore内のAES-GCM暗号化された確認履歴を読み込むだけ。
2. 保存済みPCの**完全な64文字の指紋**を見て、ユーザー自身が比較対象を選ぶ。履歴が未保存・破損していれば、空・エラーを明示し、自動的に別のPCを選んだり履歴を書き換えたりしない。
3. PC側に新しい使い捨てQR-v3を表示し、スマホで読み込む。
4. 選んだ指紋とQR-v3の`pc`値が**一致**した場合だけ、その旨を「本人認証は未完了」と明記して表示。従来通り、PIN留めTLS証明書検証、6桁確認コード、PC利用者の`YES`、PC・Android双方のP-256署名検証とスマホ側の明示承認が必要。
5. 指紋が**不一致**、または相手が端末公開鍵のない旧QR-v2だった場合は、QR招待・TLS指紋・確認状態を破棄して、接続確認を停止する。PCの鍵変更・別PC・すり替え等の可能性として表示し、PCの端末キーを調べ直して**新しいQRを発行して再読取**してもらう。
6. 新しい鍵へ意図的に移行する場合は、ユーザーが「過去の指紋との比較を解除」を押して明示的に比較状態を解除し、新しいQR-v3を発行・読取して再度相互署名する。解除しても**同じ画面内で指紋不一致を理由に拒否されたQR招待IDは再スキャン時に拒否**し、新しいQR招待IDが必要。画面の再生成・アプリ再起動を越えた拒否IDの永続記録ではないが、短命招待・毎回のPC承認・署名検証は維持する。旧履歴は勝手に消えず、必要なら確認履歴画面で手動削除する。

## セキュリティ境界

- 比較対象は**自動選択しない**。mDNS名、IP、機器の見た目、同名PC、過去の通信などからPCの同一性を推定・信頼しない。
- 選んだ指紋と一致しても、接続・リモート操作・自動再接続・ファイル送受信・通信監視・権限付与・遠隔失効は一切行わない。保存済みの指紋を恒久認証に使わず、毎回新しいQR-v3と双方の署名検証が必要。
- 比較対象を選んでいる間は、手入力モードや旧QR-v1/v2へ**暗黙にダウングレードしない**。選択解除で新しいQRを要求する。
- アプリが一時停止・ロック・背面移行・中止になれば、選択した比較対象やQR状態を破棄する。保存済み暗号化履歴自体には影響しない。
- 履歴読み込みや署名のネイティブAPIを `.chappy` JSに新規公開しない。AndroidネイティブのP-256鍵・AES鍵、既存アプリデータ、APK署名、リリース設定を変更しない。
