# NETLAB-03B-4A — 一回限りの双方向署名確認と双方承認（オフライン基盤）

**状態：ソース実装／自動テスト対象。QR-v2通信への接続前。実機ペアリング、登録済み端末、正式APKは未実装・未公開。**

## 今回追加

\`examples/windows_companion/mutual_proof_session.py\` は、前段階のP-256署名・検証モジュールを使って、双方の本人鍵所有証明が同じ一時接続に属するか判定する、単一セッション専用の状態機械。

- PC検証者が32バイト乱数を発行してAndroidのP-256署名を確認。
- Android検証者が**別の**32バイト乱数を発行してPCのP-256署名を確認。
- 署名内容にはrole（pc/android）、QR招待、一時TLS証明書SHA-256、相手の公開SPKI指紋、nonce、有効期限をすべて含める。別セッション、別端末、別方向への署名の流用を禁止。
- 10分以内の短期有効期限、署名の一回限り消費、重複提出・不正署名・期限切れ・拒否でセッション全体を閉じる。排他ロックで同時重複リクエストも一件のみ。
- **両方向の署名が成功した後で**PC側とスマホ側の独立した明示承認がそろう場合だけ、\`complete()\` が一度だけtrueを返す。途中完了は失敗のまま閉じる。
- 成立したとしても、実行できるのは「この一時セッションで署名と承認が通った」という判定のみ。信頼登録、再接続権、ファイルアクセス、PC制御、通信監視、バックグラウンド接続は一切付与しない。

## 明確に未完成の部分

このPythonモジュールは**LANに接続しない純粋なオフライン準備部品**。既存の\`Start-ChappyPairing.cmd\`、QR-v2のHTTPSサーバー、AndroidのFlutter画面／KeyStoreへの通信経路には接続していない。スマホ実機の署名検証も、このテストでは実行されない。

ここに渡す各端末の「期待公開鍵指紋」は署名レスポンスから無条件に信用してはならない。利用者が見ているPC画面のQR＋TLS証明書指紋、実機の独立した本人承認と安全な公開鍵交換によって、相手端末IDと紐付ける必要がある。単に新しい鍵を見つけただけでは「既知のPC」扱いをしない。

テスト対象は\`tools/test_mutual_proof_session.py\`で、両方向の成功、片側だけ成功、否認、期限切れ、役割の反転、nonce取り違え、別セッションでの署名の再利用、誤った鍵、重複送信、8並列の競合、早期completeとキャンセルを検証する。Windows Companion Preview CIで実行する。
