# NETLAB-03B 実機2台 QA マトリクス（QR-v3 / 鍵履歴 / ローカル失効）

状態：**テスト手順のみ。2026-11-08時点で実機PASSを主張しない。** この文書は開発者が Windows PC と Android を使うときの記録用。公開APKの配布判断や永続的な信頼・PC操作の実装とは別。

関連仕様：[QR-v3相互認証](pc-link-mutual-qr-v3.md)・[両側の既知鍵照合](pc-link-known-key-comparison.md)・[鍵の削除と復旧](pc-link-key-recovery-and-revocation.md)。

## 前提・安全境界

- 自分で管理する Windows PC と Android、同一の信頼できるLAN。公開Wi-Fiや第三者の端末を使わない。
- Windows Companion **プレビュー**と Android **Debug** を同じ開発時点のソースから用意。使用した Git commit SHA、APKのbuild番号、Android機種/OS、Windows版、ネットワーク種別を記録する。
- 自分の秘密鍵・認証トークン・QRの招待ID・実際の6桁確認コードをIssueやログに貼らない。必要なら**公開鍵指紋の末尾のみ**を伏字で記録。デバッグログ共有前に必ず確認。
- データ退避を済ませるまで鍵削除ケースを実施しない。既存鍵を使う通常の接続確認だけなら鍵を再作成しない。
- Android側の確認済みPC履歴、Windows側の確認済みスマホ履歴は**認証の証拠メモ**であり、恒久的な接続許可ではない。相手側への遠隔失効通知や自動再接続は存在しない。

## 操作の順序

1. **非破壊** QA-01〜09、QA-04/05の画面復帰・通信失敗を先に確認。各失敗後は新しいQRを発行する。
2. QA-10の履歴クリアは事前に保存済み指紋を匿名化して控え、再保存のため再びQR-v3の双方認証を行う。
3. QA-11は削除されないことを確認するだけ。QA-12〜14の**実際の鍵削除**は専用のテスト端末、または利用者が不可逆性を了承した後に限る。
4. 失敗のたび「何を拒否したか」「Android表示」「PCコンソール表示」「再使用を拒んだか」を記録。ネットワーク障害と証明検証失敗を混同しない。
5. PASS・FAILの結果はこの表の状態を更新するかGitHub Issueに記録。未実施の行は未実施のまま残す。
