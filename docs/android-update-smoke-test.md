# Chappy Player 固定署名APK・初回上書き更新 実機テスト

対象：Android 14 / Xiaomi 11T Pro（arm64-v8a）。2026-11-04。

## 前提

- 現在インストール済みの正式署名版は **v0.2.0 (Build 5)**。
- 次に公開する版は **v0.2.1**（Build番号は公開Workflowの実行番号が自動採番する。5より大きいこと）。
- 配信先は [chappy-player-updates の GitHub Releases](https://github.com/mibesamiti-png/chappy-player-updates/releases)。
- ビルド前に既存アプリの `.chappybackup` が 0KB でないこと、必要なメモを復元できること、`.chappy` 本体も保管していることを確認する。
- このテストでは **既存の Chappy Player をアンインストールしない**。

## 1. v0.2.1 の署名付きAPKを公開

**非公開ソースリポジトリ**の Actions → [Publish Signed APK Updates](https://github.com/mibesamiti-png/chappy-player/actions/workflows/publish-signed-apks.yml) → Run workflow：

- Branch: `main`
- version: `0.2.1`
- release_notes: `初回上書き更新の実機テスト・ホームにバージョン/Build表示`

全ステップ成功後に公開リポジトリの `update.json` が v0.2.1 を指す。**この操作は公開APKの作成・公開であり、端末へのインストールはまだ行わない。**

## 2. Androidのアプリ内更新

1. **今のv0.2.0のまま**、サンプルメモ帳を開き、判別しやすいテスト文字（例：`上書きテスト前のメモ`）を保存して閉じる。
2. Chappy Playerホーム右上の更新アイコン（システム更新）をタップ。
3. 更新センターで `現在のバージョン：0.2.0（ビルド 5）` を確認し、**最新版を確認**。
4. 配信された `v0.2.1` と、この端末向け `arm64-v8a` が表示されることを確認。
5. **ダウンロードして更新**を押す。SHA-256・APK署名・パッケージID・増加するBuild番号のチェックが完了することを確認。
6. Androidから「この提供元のアプリを許可」画面が開いたら許可して戻り、必要なら「インストールを再開」を押す。
7. **Androidのインストール確認画面で更新を承認**。既存アプリをアンインストールしない。

## 3. 上書き後の成功判定

- Chappy Playerを再起動し、ホームのタイトル直下に `v0.2.1 · Build ＜6以上の番号＞` が表示される。
- ミニアプリ一覧が残っている。
- サンプルメモ帳を開き、保存したテスト文字が消えていない。
- 更新センターで「最新版を確認」すると「現在のバージョンが最新です」と表示される。
- メモデータの復元は **不要**。上書き更新なのに復元が必要ならテスト失敗扱い。

## 問題が起きたら

- **Androidがインストールを拒否した場合、アンインストールしない。** 更新センターの「詳細」や診断ログの `apk-preflight`・`apk-installer` の内容を確認する。
- GitHub Releasesからの直接インストールは、アプリ内更新のテストが終わるまでは行わない。手動インストールに切り替えると問題箇所を切り分けにくくなる。
- 署名不一致なら、キーの作り直し・署名チェックの無効化をしない。GitHubの署名設定と検証ログを確認する。
- ネットワークエラーなら、更新フィードURL・CDN転送先・レスポンスコードを確認する。Secretsや個人メモ内容を公開しない。

## 既知の制約

- インストール操作はAndroid標準画面でユーザーが承認する必要がある（無人更新ではない）。
- 「インストール画面を開いた」時点は成功扱いしない。更新後に **端末の実バージョンと保存データ**を確認する。
- 本テストに必要なUIと配信経路は実装済みだが、アプリ内の初回上書き実機成功は**このテストで検証する**。
