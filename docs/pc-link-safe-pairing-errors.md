# NETLAB-03B: PC接続確認の安全なエラー表示

AndroidのPC接続確認画面は例外全文を画面に表示せず、安定した診断コードと対処案を表示する。対象は信頼済みFlutterホスト画面で、.chappy JavaScriptへ追加APIは公開しない。

| コード | 主な分類 | 確認すること |
| --- | --- | --- |
| PAIR-TLS | TLS/証明書のハンドシェーク | 新しいQRとPC側の証明書指紋 |
| PAIR-NET | ソケット通信 | Wi-Fi、同一LAN、Companion起動、ファイアウォール |
| PAIR-TIME | 応答タイムアウト | PC側の承認画面と新しいQR |
| PAIR-FORMAT | 不正な入力・QR・応答 | 期限切れ、QR再取得、プロトコルのバージョン |
| PAIR-HOST | Androidプラットフォーム連携 | アプリの状態・ホスト機能 |
| PAIR-STATE | 承認・鍵・使用済みQRなどの状態 | 両側の承認、端末鍵、QR再取得 |
| PAIR-OTHER | 分類不能 | 手順だけ記録して再現確認 |
| HISTORY-READ / HISTORY-SAVE | ローカルの履歴読込・保存 | 端末の保存状態 |

**重要:** 分類は診断の補助であり、特定原因の確定ではない。例えば `PAIR-STATE` はAndroid側で拒否した場合とPC側で拒否した場合を自動判別できない。

セキュリティ方針：例外の `toString()`、TLS証明書、QR招待ID、nonce、署名、端末鍵、公開鍵指紋、個人ネットワークアドレスを、この機能からユーザー向け診断文字列へ埋め込まない。画面表示だけを変更し、通信の再試行・認証・失敗時のQR消費・権限判定は一切変更しない。

## 動作確認

- `flutter test test/pc_pairing_failure_test.dart`：主要分類・秘密文字列がメッセージに入らないこと。
- `flutter analyze` と `flutter test`：画面との統合による回帰確認。
- 実機QA：[2台での確認マトリクス](pc-link-two-device-qa-matrix.md)（PR #78。未統合の場合はリンク先PRを参照）。
- 画面のエラーコードはユーザーが再現手順に添えてよいが、開発者向けのデバッグログ全文を送る場合は必ず手動で機密文字列を除外する。

**実機・CI未検証のコードを正式APKの安全性証明とは呼ばない。**
