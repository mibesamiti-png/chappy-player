# Chappy Player — ワンタップ更新（開発中）

2026-11-04 / Xiaomi 11T Pro（Android 14）でのテスト結果を反映。
**コード実装段階。GitHub Actionsで解析・APK生成、実機検証が必要。**

## 目指す操作

1. Chappy Player の右上から「プレイヤー本体の更新」を開く。
2. 「最新版を確認」→更新があれば「ダウンロードして更新」。
3. 端末のCPU形式に合うAPKをHTTPSで取得し、実サイズとSHA-256を検証。
4. AndroidのPackageManagerで同一アプリID・完全一致の署名証明書・増加したversionCodeを確認。
5. Android標準のインストーラーを開く。ユーザーが「更新」などを押して承認。
6. 初回だけ「この提供元からアプリをインストール」を許可する必要がある場合、設定を開き、戻って「インストールを再開」を押す。APKの再ダウンロードは不要。

APKをZIPから解凍したり、手動でファイル管理アプリを起動したりする工程は不要になる。

**Androidの確認なしにインストールする機能は設けない。** インストール画面を開いた時点で成功扱いせず、Android側の操作結果に委ねる。

## 防御機構

- 公開HTTPS更新フィードからのみ取得し、リダイレクトを拒否
- CPU形式（ARM64など）を自動選択
- ダウンロードが完全かSHA-256で照合
- Android側でAPKのアプリID、署名、増分versionCodeを事前照合
- 不一致ならインストール画面を出さずに中止。アンインストールもしない
- APKはアプリのプライベートキャッシュ内`chappy_updates`で保持
- AndroidX FileProviderでそのディレクトリに限定したcontent URIを発行
- Androidのインストーラーに必要な読み取り権限だけ一時付与
- 端末の不明なアプリインストールの許可は本人が操作
- Android端末へインストールされたことを確認する処理は今後の改善項目

## **まだ準備が必要なもの**

- **固定署名キーストア**：今のGitHub ActionsデバッグAPKはビルドごとに署名が変わり得る。以前確認した署名競合を解消するには、同じキーストアでビルドし続けなければならない。
- **公開可能なAPK更新配布先**：ソースのGitHubリポジトリは非公開。アクセストークンをAPKに埋め込むのは禁止。APKだけ公開してよいなら、別の配布専用リポジトリ／HTTPSストレージを用意する。
- **配布URL**：GitHub Actionsの手動署名ビルドは、Repository variable `CHAPPY_UPDATE_FEED_URL`をビルド時に埋め込める。
- **更新フィード**：`tools/generate_update_feed.py`で署名済みAPKからバージョン・URL・サイズ・SHA-256を作成する。

署名・配布先が未設定の場合、更新センターは安全のため「未設定」と表示して、勝手に接続しない。

### 現在のデバッグAPKに関する注意

固定署名版へ初めて切り替えるときは、現在インストール済みの使い捨てデバッグ署名と互換性がない可能性が高い。
**0KBではないバックアップを端末外に保存・復元できることを確認した上で**切り替えること。
その後は固定署名と増加するビルド番号を維持すれば、更新ごとにアンインストールする必要はなくなる。

Google Playへの公開を計画する場合、`REQUEST_INSTALL_PACKAGES`を使用した自己更新はポリシー制限がある。現仕様は個人用・サイドロード運用が対象。
